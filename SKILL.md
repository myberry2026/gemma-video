# Skills - Gemma Video

- **Python Environment Resilience**: Encountered a case where the project's `venv` was merely a set of symlinks to a system Python lacking key dependencies. Learned to use `virtualenv` as a robust fallback when `python3 -m venv` fails due to missing `ensurepip` or system-wide restrictions.
- **Naming Inconsistency Pitfalls**: Discovered that mismatches between internal function names (`select_diverse_7_from_pool`) and external verifier calls (`select_diverse_7_from_16`) can block system-wide validation. Maintaining a strict API contract or using shared utility modules across all scripts is crucial for long-term maintainability.
- **WSL2 ADB Migration**: Transitioning from a Windows-hosted ADB symlink to a native Linux ADB package in WSL2 prevents cross-platform execution overhead and potential compatibility issues. Ensuring the local ADB server is used avoids reliance on the host OS's Android SDK path.

- **Ktor/Coroutine Engine Compatibility**: Discovered a critical `NoSuchMethodError: LockFreeLinkedListHead.addLast` crash when using Ktor 2.3.x with default `CIO` engine on Android. Learned that `Netty` is significantly more stable for embedded Ktor servers in Android environments when paired with `kotlinx-coroutines` 1.8.x. Aligning `coroutines-core` and `coroutines-android` versions explicitly is mandatory to prevent classpath conflicts during R8/ProGuard processing.
- **On-Device Large File Management**: Implementing a 2.4GB model downloader required handling partial downloads (resumability) and background execution within the `MainActivity` lifecycle scope using `lifecycleScope`. Using `.tmp` files and `renameTo` is a robust pattern for ensuring model integrity before loading.
- **Android 14+ Foreground Service Mandatory Types**: Learned that targeting API 34+ (Android 14) requires explicit `foregroundServiceType` declarations in the manifest AND matching permissions (e.g., `FOREGROUND_SERVICE_SPECIAL_USE`). Additionally, `startForeground()` must now include the service type as a parameter, and a `<property>` tag for `SPECIAL_USE` types is required to pass Play Store and system-level validation.

- **LiteRT Backend Alignment**: Found that `LiteRT-LM` for Android defaults `visionBackend` to `GPU` even if the main LLM `backend` is set to `CPU`. This can cause initialization failures on devices where the GPU (specifically the OpenGL delegate) is incomplete or buggy. Aligning both backends to `CPU` or `NPU` (MediaTek APU) resolves these 'INTERNAL' engine creation errors.
- **Android MediaPipe/LiteRT Permission Sandbox**: When loading models from `/sdcard` using `LiteRT-LM`, the app needs both `MANAGE_EXTERNAL_STORAGE` and proper file path mapping. Copying the model to the app's internal `files/` directory is the most reliable way to avoid 'Permission Denied' errors during native engine initialization, especially when using `run-as` for debugging.
- **MediaTek Mali-G615 GPU Delegate Limitations**: Identified that current LiteRT OpenGL delegates may fail with `UNIMPLEMENTED: CreateSharedMemoryManager` on newer Mali-G series hardware. In such cases, the `NPU` backend (NeuroPilot) often provides a functional and performant alternative to standard GPU acceleration.
- **Multi-Channel Curation Control**: Implementing "Manual Trigger Refinement" across three channels (Shell/ADB, Mobile UI, Web API) highlighted the importance of a centralized business logic layer (`performManualRecap` in the service) that can be invoked via multiple entry points (Intents, HTTP routes).
- **Embedded API Orchestration**: Extending the mobile Ktor server to support action-oriented endpoints (like `/refine`) demonstrates how a phone can behave as a first-class citizen in a multimodal AI pipeline, handling both data ingestion and high-level processing requests.
- **Glassmorphic Acceptance Testing**: Validating PRD requirements through direct code implementation and UI alignment ensures that the final "Demo" experience matches the partner's vision for a "clean, pure input" system.
